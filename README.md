# 新竹公車 · 站牌看板（示範版）

以站牌為主軸的公車到站看板。純前端、資料全部是模擬的，
**在 VS Code 打開資料夾，雙擊 `index.html` 就能看**，不用安裝任何東西、不用申請金鑰。

---

## 這個示範想證明三件事

### 一、主軸應該是站牌，不是路線

現行系統逼你先選路線再看到站時間。但站在站牌前的人想的是
「我站在這裡，接下來會來什麼車」，不是「我要查 81 路」。

這裡把主軸翻過來：**一個站牌之下，所有經過的路線混在一起、依到站時間排序**。
你不需要知道自己該搭哪一號，看最上面那台就對了。

### 二、要讓人看得出資料是不是舊的

「公車資訊更新不及時」真正折磨人的地方，不是資料舊，
而是**畫面上看不出它舊**。你盯著一個「5 分鐘」等了二十分鐘，才發現那個數字從頭到尾沒動過。

所以頁首那條橫條代表資料還有多新，每次更新就填滿、然後慢慢退掉：

| 資料年齡 | 畫面反應 |
|---|---|
| 60 秒以內 | 強調色為綠 |
| 60 秒 – 3 分鐘 | 轉琥珀色，標示「資料延遲中」 |
| 超過 3 分鐘 | 轉灰，明講「現在的數字不可信」 |

另外每一筆到站時間都標了來源：**車機定位**是真的有車在回傳位置，
**時刻表推估**是照班表算的、路上沒有實車資料。這兩種在現行頁面長得一模一樣，
但可信度差很多。

### 三、事故發生時，應該直接告訴人怎麼辦

這是簡報第一期「智慧應變」那一段。按下頁面下方的**「模擬光復路事故」**，
到有 81 路經過的站牌（例如清華大學）看看：系統會標出延誤，
並列出**同一站也能到達相同目的地的其他路線**，附上各自的到站時間。

不是丟一則「81 路延誤」的通知就沒事了，而是把「那我現在該搭什麼」直接算出來。

## 其他升級

- **路線色**：每條路線有自己的顏色，一眼能分。現行頁面全部是同一個灰。
- **展開看沿線**：點任何一列會攤開整條路線的站序，車輛位置標在對應的站旁邊，而且會動。
- **收藏站牌**：點星號，下次打開還在。
- **放大字級**：右上角那顆「字」。站在站牌前、光線不好或長輩要用的時候，這比什麼都實用。
- **附近站牌**：按了會要定位權限；不給也沒關係，會退回以新竹火車站為基準，示範不會卡住。

## 檔案結構

```
index.html          畫面結構
css/style.css       樣式（顏色、字級都在最上面的 :root 裡）
js/data.js          模擬資料：站牌、路線、班距、營運時間
js/sim.js           模擬引擎
js/ui.js            畫面繪製
js/app.js           狀態管理與事件綁定
```

### 模擬引擎在做什麼

沒有寫死任何一個到站時間。作法是讓**車真的沿著路線在跑**：

1. 每條路線有發車間隔，第 k 班在「首班時間 + k × 班距」發車。
2. 現在時間減發車時間 = 這班車已經跑了幾秒。
3. 某一站的到站時間 = 這站的累積行駛秒數 − 車已跑的秒數。

所以看板上的分鐘數、路線圖上車的位置、線上有幾輛車，
三者永遠一致，點開來不會露餡。事故就是給那條路線加一段延誤秒數，
其餘全部自動跟著變。

時鐘跟著你電腦的真實時間走，所以早上看跟晚上看會不一樣
（15 路九點才首班，早上去看會顯示「尚未發車」）。
如果現在是深夜、全部路線都收班了，程式會自動把模擬時間挪到早上八點十五分，
免得畫面一片空白。

## 想改哪裡

| 想做的事 | 改哪裡 |
|---|---|
| 換配色 | `css/style.css` 最上面的 `:root` |
| 加站牌或路線 | `js/data.js` 的 `STOPS` 與 `ROUTES` |
| 調班次密度 | `js/data.js` 裡每條路線的 `head`（秒） |
| 改「多久算過期」 | `js/ui.js` 的 `STALE_AT` / `DEAD_AT` |
| 換事故地點或延誤長度 | `js/sim.js` 的 `raiseIncident()` |

## 之後若要接真實資料

模擬資料的欄位是刻意照著交通部 TDX 平臺的格式取的，
換成真的只要重寫 `js/sim.js` 的 `board()` 和 `estimate()`，
`ui.js` 和 `app.js` 完全不用動。

要注意 TDX 走 OAuth，金鑰不能放在前端，需要加一層很薄的後端代管金鑰。
